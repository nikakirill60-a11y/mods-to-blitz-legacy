# resviewer — просмотр файлов игры без распаковки

`resviewer.py` открывает файл игры (любого размера) и показывает, что у него
внутри. Файл читается прямо с диска; ничего не распаковывается, пока вы сами
не нажмёте «Сохранить выбранное».

| Файл | Что покажет |
|---|---|
| `resources.assets.resS` (Unity) | какие картинки / звуки / модели лежат по каким адресам (нужен `resources.assets` рядом и UnityPy); без него — вложенные файлы по сигнатурам |
| `resources.assets`, `*.assets`, `globalgamemanagers` (Unity) | все объекты и их поля, картинки, **имена классов кода игры** (MonoScript) |
| `.pck`, `.exe` со встроенным пакетом (Godot 3 / 4) | список файлов внутри, **текст скриптов `.gd`**, имена полей из скомпилированных `.gdc` (в том числе сжатых), строки из ресурсов `.res` |
| любой файл | поиск слов, текстовые строки, hex |

Кнопка **«Барабан»** ищет сразу все слова, связанные с барабаном / магазином:
`burst, intrashot, cycle_info, fire_mode, volley, clip, magazine, drum, shots,
shell_count, autoload, reload`. Слова находятся и в обычном тексте, и в UTF-16,
и внутри скомпилированных скриптов Godot (там имена закодированы XOR 0xB6, а в
Godot 4.3+ ещё и сжаты zstd). У каждой находки видно, в каком файле или объекте
она лежит.

## Установка

1. Python 3.8 или новее: https://www.python.org/downloads/. При установке
   поставьте галочку **Add Python to PATH**.
2. По желанию, для полного разбора (в командной строке Windows):
   ```
   pip install UnityPy zstandard
   ```
   * `UnityPy` — объекты Unity, их поля и картинки из `.resS`;
   * `zstandard` — сжатые скрипты Godot 4.3+.

   Без них поиск, строки, hex и список файлов `.pck` тоже работают.

## Запуск

* **Windows:** перетащите файл на `resviewer.bat`, или запустите его двойным
  щелчком и нажмите «Открыть файл…».
* Или из командной строки:
  ```
  python resviewer.py                        окно
  python resviewer.py resources.assets.resS  окно, сразу с файлом
  ```

### Вкладки окна

* **Внутри файла** — список файлов / объектов. Щелчок показывает содержимое
  справа; есть фильтр по имени, «Показать картинку» и «Сохранить выбранное…».
* **Поиск** — любое слово или кнопка «Барабан». Двойной щелчок по находке
  открывает файл / объект, в котором она лежит, или место в hex.
* **Строки** — все читаемые строки файла (можно фильтровать по слову).
* **Hex** — байты с любого адреса.

### Консольный режим (без окна)

```
python resviewer.py ФАЙЛ --drum                  слова барабана
python resviewer.py ФАЙЛ --find intrashot --find clip
python resviewer.py ФАЙЛ --list                  что внутри
python resviewer.py ФАЙЛ --show 12               элемент №12 из --list
python resviewer.py ФАЙЛ --show burst_info       ... или по части имени
python resviewer.py ФАЙЛ --strings --min 6 --filter burst
python resviewer.py ФАЙЛ --hex 0x1F400 --length 512
```

Чтобы сохранить результат в файл: `python resviewer.py ФАЙЛ --drum > drum.txt`.

## Где искать настройки барабана

* В **`.resS`** лежат только «сырые» данные: пиксели, звук, вершины. Текста и
  настроек там обычно нет.
* В Unity-играх настройки и код описаны в **`.assets`** (объекты MonoBehaviour)
  и в `Managed/Assembly-CSharp.dll`. Имена классов видны в списке как MonoScript.
* Игра, под которую в этом репозитории делаются моды, сделана на **Godot**.
  Барабан описывают скрипты `assets/data/tank_info/burst_info.gd`,
  `cycle_info.gd` и `module_gun.gd` внутри **`.pck`** игры (или `.exe`, если
  пакет встроен). Откройте этот файл, найдите скрипты во вкладке «Внутри
  файла» — там будут названия всех полей барабана.

## Ограничения

* Зашифрованные файлы (`.pck` с ключом шифрования игры) не прочитать без
  ключа. Программа помечает их замком, но поиск по всему файлу работает.
* Объекты MonoBehaviour без скриптов игры показываются как сырые байты и
  строки: их поля описаны в коде игры.
